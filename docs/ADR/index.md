# 架构决策记录（ADR）

> **这里只写「为什么这样做」**，不写「现在是怎么做的」——现状表、目录树、API 表、环境变量都在 `Develop_Document.md` / `README.md`。
> 判断标准只有一条：**十年后有人问「当时为什么选了这条」时，答案能不能在这里找到**。像「SM4 在本机实测慢 17 倍且 Node 没有 AEAD 模式」这类附带实测数据的取舍，以及「自签名证书换不来安全上下文、只会给出假的安全感」这类反面理由，一旦丢了就很难在同一处再复原一次——它们正是这个目录存在的理由。

## 什么时候写一条 ADR

改动涉及**不可逆或高成本回头**的取舍时写：换算法、换存储方案、引入或移除依赖、改变部署形态、向外部（浏览器 / 客户端）承诺的行为。修补一处 bug 不需要 ADR。

不要删已有的 ADR：决定被推翻时写一条新的，**保留被取代的记录**（把旧条目标注「已被 ADR-XXXX 取代」并链接过去）。

## 格式要求（由 `tests/docs-sync.test.js` 强制）

- 文件名 `NNNN-slug.md`，编号从 1 起，空前缀零填充到 4 位；
- 必须包含五个小节：`## 背景`、`## 决定`、`## 理由`、`## 备选方案（已否决）`、`## 后果与需要长期遵守的约束`；
- 必须在本文件的索引表里占一行，且**编号与文件名前缀一致、标题与该文件的 `H1` 一致**；
- Markdown 表格一律紧凑型（`| a | b |`）。
