# ADR-0006: 每条修复都要行为护栏 + 反向对照台账（撤销必须变红）

- 状态：已采纳
- 提出时间：未归档
- 相关：`tests/*.test.js`、`scripts/reverse-check.js`、`tests/invariants.test.js`

## 背景

早年的护栏大多是两类：单测（断言返回值）与静态文本断言（断言源码里有某个串）。它们在两个难题面前都失效：

- **文本断言会被注释满足**：`assert(!/gen_self_signed/.test(src))` 会被一句解释「为什么删掉它」的注释满足——写注释的人是在做正确的事，却把护栏变成了摆设。
- **判据落在没有执行的那一层**：R38 的一条对照断言 `deploy.sh` 源码里有 `SITE_DOMAIN=${DOMAIN}` 那一行，**照样是绿的**，而用户侧的故障正在发生（真正跑起来的脚本不是这一份）。

「源码里有这一段」不等于「跑起来会执行这一段」。

## 决定

每一次修复都必须配两样东西：

1. **一条行为护栏**（真的把进程 / 函数 / HTTP 端点跑起来后再断言）；
2. **一条反向对照**（登记在 `scripts/reverse-check.js` 的 `CASES` 台账里）：把修复**撤销成旧实现**，跑指定测试文件，`fail` 数必须达到下限，且**红的必须是对应的那一条用例**。

后者是这套方法里真正的杠杆——它回答的不是「测试通不通过」，而是「这条护栏到底有没有打在该打的地方」。

## 理由

- **`fail=0` 就等于护栏没打在该打处**，这是最贵的一条经验。它以三种形态反复出现：判据比名字弱（判「存在」而两处同串，删一处仍绿）、判据落在旁边的那一层（源码里有这个词，那条路径却从未执行）、判据的执行条件压根没被触发（例如写入端的低水位线从未达到，背压分支始终不跑）。
- **anchor 的唯一性直接决定对照是否可信**：`runCase` 用 `indexOf` 定位且**只替换首处**，若那段字面量在源码里出现两次（包括出现在注释里），变异就打偏了；因此有 `invariants.test.js` 常驻自检（双侧剥注释后比对）。
- 台账是**总数与 `minFail` 共同对账**的：撤销力度变弱会表现为「红的条数变少」而不是变红——所以每次要问「**应该红几条**」，而不只是「有没有红」。

## 备选方案（已否决）

| 方案 | 否决理由 |
| --- | --- |
| 只写正向测试 | 「护栏绿了」与「护栏真的在守这条路」是两件事，这一整套机制存在的意义就是前者不能代替后者 |
| 用覆盖率代替反向对照 | 覆盖了不等于断言正确；它也回答不了「判据有没有被别的东西满足」 |
| 每次提交串行跑满全量对照 | 每条都要起一次子进程，成本高且互相干扰；故支持按前缀过滤（`--only=`，位置参数一律报错），按需跑而不是常态跑 |

## 后果与需要长期遵守的约束

1. **每登记一条 CASES 都必须真的跑一次**，并同时回答「红的是不是本条」与「应该红几条」两个问题。
2. 改变形状（把单行 `return` 展开成块、把内联实现收口成函数）会**老化别人已登记的 anchor**：改完先跑 `invariants`，它是兜网。
3. 环境相关的用例缺失环境时必须 `skip` 并写明原因——「报告通过但从未执行」比硬失败更坏（`audit40` 的 `t.skip()` 就是这么来的）。
4. 突变前会把原文件落成 `.reversebak`；被 `timeout` 或强杀会留下变异态源文件，事后要查残留。
